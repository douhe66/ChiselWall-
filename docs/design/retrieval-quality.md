# 检索质量通用改造（P0.5）：查询理解 + 召回阶梯 + 置信分层

> 版本 v0.7.2。目标：把「文件锁怎么用 → 文件外发审批/git lfs」这类失败从个案修复升级为通用机制，并建立可回归的评测。

## 1. 问题

`文件锁怎么用` 经 jieba 切成 `文件/锁/怎么/用` 后：
- 停用词 `怎么` 被过滤、单字 `锁/用` 被丢弃 → 查询塌缩成 `文件`；
- `jieba_or` 兜底把全库所有含「文件」的文档都召回（文件外发审批、文件导入导出、git lfs）；
- 这些弱相关结果还会进入 AI 上下文，挤占预算。

## 2. 通用设计（五层）

### 2.1 查询理解（src/indexer/jieba_util.py）

- `query_phrases(query)`：从**原始查询**生成短语候选，不依赖分词；
  - 先剥离问句词（怎么/如何/是什么/吗/呢…）；
  - 单段查询：整段 + 所有 3-gram；多段查询（空格/英文词）不生成短语，交给 AND；
  - 过滤高频泛词（`GENERIC_TERMS`：文件/系统/方法/数据/配置…）；
- 短语匹配同时覆盖「原文短语」与「分词后短语」（如 `文件锁` 与 `文件 锁`），解决跨分词边界。

### 2.2 召回阶梯（src/searcher/search.py）

1. **连续短语**（从长到短，命中即停）；
2. **全词 AND**（有效词 ≥2）；
3. **问句覆盖 OR**（仅问句）：单泛词/单字不放行；至少要有一个**非泛词**命中；
4. **trigram / LIKE 兜底**（短查询）；
5. 向量融合（P0 门槛：相似度 + 词面证据 + 限条）。

### 2.3 置信分层（SearchHit.tier）

- `strong`：短语 / AND / 混合 / 高置信向量；
- `weak`：`jieba_or` / trigram / LIKE；
- UI：弱相关默认折叠在「弱相关结果（N 条，默认不进 AI）」；
- **AI 上下文只取 strong**；没有 strong 时明确回答"资料中没有找到"，不拿噪声硬答；
- rerank 只对 strong 候选生效。

### 2.4 AI 过滤（src/node/agent.py）

- `ai_answer()` 过滤 `tier == weak`；
- `rerank_hits()` 过滤 weak，weak 原样附在结果末尾。

### 2.5 评测闭环

- `tests/fixtures/golden/queries.json`：6 条真实问题（复合词/多词/英文混合/泛词）；
- `tests/eval_retrieval.py --db <库>`：recall@5、nDCG@10、弱相关占比；改检索前后必须对比；
- `tests/test_retrieval_quality.py`：合成语料的回归单测（短语、泛词、多词）。

## 3. 结果（真实库 241 篇）

| 查询 | 改造前 | 改造后 |
|---|---|---|
| 文件锁怎么用 | 文件锁 + 文件外发审批 + 文件导入导出 + git lfs（弱相关混入） | **只返回《文件锁》（strong/hybrid）** |
| 文件锁 | 文件锁 + 泛匹配 | 《文件锁》第 1 |
| 进程启动参数 | 正常 | 第 1 |
| cgroup 内存限制 | 正常 | 第 1 |
| 文件导入导出 | — | 第 2（第 1 为《数据库索引》，待调短语权重） |
| git lfs | — | 第 1 |

评测：**recall@5 = 1.00，nDCG@10 = 0.938，avg_weak = 0.00**（6 条）。

测试：**266 项全绿**（新增 retrieval_quality 4 项 + eval 脚本）。

## 4. 边界与后续

- 短语候选只取 3-gram：极短/极长复合词、同义词仍可能漏；
- 泛词表是静态清单，后续可换成 IDF/文档频率自动权重；
- 弱相关默认折叠，但用户可展开；
- 下一步：P1.1 rerank 缓存/卸载/golden 扩充；P2 查询改写（多查询/HyDE）提升同义召回。
