# M5 验收报告（AI 入口）

> 范围：设计 §10——OpenAI 兼容 LLM 接入（DeepSeek / 内网模型 / Ollama）、提问者侧 RAG 综合（带引用）、配置界面。
> 结论：**链路通过**（230 项单测全绿 + 假模型 E2E；真实内网模型需用户配置后验收）

## 1. 实现

| 组件 | 文件 | 说明 |
|---|---|---|
| LLM 客户端 | src/ai/llm.py | OpenAI 兼容 /chat/completions；配置持久化 ~/.chiselwall/ai.json；key 掩码；超时/错误处理；系统代理开关 |

## 2. 验证（假模型 E2E，真实数据）

- 用本地 OpenAI 兼容假模型（127.0.0.1:18800）配置后：/api/ai/test 连通 46ms；
- 提问「fcntl 怎么加锁」（数据库组）：聚合 2/2 节点（@我 思源笔记 + @bob），AI 综合 31ms，上下文 484 字符；
- 引用列表：[1]《文件锁》@我（.sy）、[2]《bob-fcntl》@bob（.md）——引用可追溯；
- 浏览器实测：AI 问答页显示「AI 已就绪 · 模型名 · relay 已连接 · 在线 3 人」，答案与引用正常渲染；
- 230 项单测全绿（M5 新增 10 项：上下文编号/预算/topN/空片段、LLM 桩服务、错误透传、配置掩码）。

## 3. 环境注意

- 本机系统代理（127.0.0.1:7890）会拦截 localhost 请求（httpx trust_env 导致 502）→ AI 客户端默认直连，设置页提供「使用系统代理」开关；
- 真实内网模型：用户在设置页填写 base_url/model/key 后「测试连接」→ AI 问答页即可用；
- 演示配置已清空，避免假模型答案误导。

## 3.3 AI 回答排版优化（M5-FIX3，v0.5.4）

- 回答由纯文本改为 **Markdown 渲染**（前端自研安全子集渲染：段落/标题/有序无序列表/加粗/行内代码/代码块，先转义 HTML 防注入）；
- 文中 `[1]`、`[2]` 自动变成可点击引用徽标，跳转到下方对应引用条目（`:target` 高亮）；
- 排版样式：行高 1.75、列表缩进、行内代码/代码块底纹、引用徽标底色；
- 增加「复制回答」按钮（复制 Markdown 原文）。

实测（真实 DeepSeek deepseek-flash）：回答渲染为 `<p>/<strong>/<ol><li>/<code>` 结构，6 个可点击引用徽标，AI 用时 4187ms。

## 3.4 关键 Bug 修复 + 布局优化（M5-FIX4，v0.5.6）

**Bug：AI 说"资料里没有完整步骤"，但笔记原文有完整代码块。**
根因：RAG 上下文用的是搜索结果片段（约 150 字），代码块在片段之外；模型只能看到简介句，自然回答"没找到"。
排查过程：查库确认该思源笔记共 7 个分块/4971 字，`struct flock` 代码在 seq=1 的块里；命中块取的是别的块，相邻窗口没覆盖。

修复：
- 本地命中（本机笔记）在送模型前用**真实分块文本**替换短片段：小文档（≤5000 字）给全文，大文档给"命中块 ± 相邻块"窗口（3000 字）；
- 单个片段上下文预算提高到 5000 字（总预算仍由 max_context_chars 控制）；
- 同步修复：`max_tokens` 默认 800 会把长代码答案截断（实测输出停在代码中间）→ 提升到 2000，并在前端对未闭合代码块自动补全，避免整段变散文本。

验证（真实 DeepSeek deepseek-flash + 用户真实思源笔记）：同一问题「fcntl 怎么加锁」→ 上下文 484 → **5147 字符**；回答包含完整 C 示例（`struct flock`、`F_WRLCK`、`F_SETLK`、`F_UNLCK`）与要点列表、引用 [1][2]。

**布局**：AI 综合开启时两栏（左 AI 回答、右搜索结果），AI 关闭时结果居中单栏；窄屏自动单列。

## 3.5 搜索结果渲染 + 提示词可编辑（M5-FIX5，v0.6.0）

| 需求 | 实现 |

| 片段太短/断句难看 | 本地命中展示片段加长为命中块 ± 相邻块窗口（最多 1200 字），默认折叠 + 渐变，点「展开片段」看全；实测《文件锁》片段 1160 字含代码块与列表 |

内置默认提示词：只依据资料回答、不得编造、[n] 引用、资料不足明确说明、Markdown 输出。

## 3.6 远端结果全文预览（M4.1，v0.6.1）

- 问题：搜索结果第二条来自 bob 的机器，没有「预览全文」按钮（文件不在本机）。
- 实现：新增 `fetch` / `fetch_result` relay 消息与 `POST /api/fetch`；远端结果新增「预览远端全文」按钮。
- **安全边界**：源节点只允许返回「最近 10 分钟内、曾作为本次搜索结果回传给该提问者的文档」（`_allowed` 白名单），其余一律拒绝；按请求者限流（0.2/s，burst 4）；返回截断 8000 字；relay 仍不落盘。
- 实测：用户实例问「fcntl」→ 结果二 @bob → 预览远端全文 → 返回 bob 的完整笔记并渲染；未授权 doc_id 请求返回 502。
