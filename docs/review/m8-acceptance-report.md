# M8：随手问会话（列表 / 历史 / 逐轮追问）验收报告

> 版本 v0.7.8。按用户澄清：不新增独立 AI 问答入口；**会话管理直接做进随手问**，像 DeepSeek 会话一样：左侧会话列表、历史会话、逐轮追问。

## 1. 交互

- 随手问左侧：会话列表 + 新建 / 改名 / 删除；
- 首条问题：广播给在线同事（保留提问组选择）；
- 同一会话后续消息：**追问，不再广播**，基于上一轮聚合结果；
- **搜索结果先出、AI 回答后出**：右侧独立结果栏展示本轮命中，先看原文再决定是否综合；
- 提问按钮旁有 **「AI 综合」勾选**：勾选=本轮结果回来后自动综合；不勾=只展示结果，点按钮再综合；偏好记忆在 localStorage；
- **会话级「AI 综合」按钮**：随时可手动综合当前结果（可重复点，追加回答）；
- 每轮显示：问题、AI 回答、引用、**搜索耗时**、**返回同事明细（@谁 / 耗时 / 条数）**；
- 命中保留旧版能力：片段高亮/展开、原文预览、**打开所在位置 / 直接打开**、远端全文预览；
- 长内容在各自框内滚动（会话区 / 结果栏 / AI 回答），不撑整页；
- 右栏可拖动分隔条调整宽度（260–760px），宽度记忆到 localStorage；
- 历史会话可随时点开回看（消息持久化在 SQLite）。

## 2. 数据与流程

- 表：`ask_sessions` / `ask_turns`（问题、回答、payload：qid/groups/aggregated/citations）；
- 首问：
  1. `POST /api/ask-sessions/{sid}/ask` → 广播，返回 qid + turn_id；
  2. UI 轮询 `/api/ask/{qid}` 收集结果；
  3. 完成后 `POST /api/ask-sessions/{sid}/complete` → 存聚合结果 + 生成 AI 回答并存 assistant turn；
- 追问：`POST /api/ask-sessions/{sid}/followup` → 取上一轮聚合结果 + 历史，直接生成回答，不广播；
- 会话 CRUD：`GET/POST /api/ask-sessions`，`GET/PATCH/DELETE /api/ask-sessions/{sid}`。

## 3. 实测

| 场景 | 结果 |
|---|---|
| 新建会话 → 首问「文件锁怎么用」 | 广播命中 文件锁 + bob-fcntl，AI 回答完整（含 flock/fcntl 示例） |
| 同会话追问「那 Java 里怎么用？」 | 不广播；回答明确说明资料没有 Java 内容，引用 [1][2] |
| 左侧会话消息数 | 首问后 2 条，追问后 4 条 |
| 改名 / 删除 / 重新打开 | 正常，历史保留 |

## 4. 与旧版的关系

- **已撤掉独立的「AI 问答」入口**（用户澄清不需要两个入口）；
- 原 M8 的 AI 会话存储保留为内部能力，但随手问使用新的 `ask_sessions` 持久化；
- 旧 `/api/ask/{qid}/followup` 保留兼容，但主流程走会话接口。

## 5. 限制

- 追问固定沿用上一轮聚合结果；要重新广播请新建会话（后续可加"重新搜索"按钮）；
- 聚合结果持久化上限 30 条/轮；完整片段仍以 qid 生命周期为准；
- 首问 AI 综合约 4–14s（取决于上下文长度与模型），期间显示"AI 综合中…"。
